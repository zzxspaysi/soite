# Проверка безопасности ANADO

Дата: **24 октября 2026**. Проверены исходники магазина, маршруты API, работа с SQLite, клиентская корзина, адаптер ЮKassa, контракт 1С, Dockerfile и вспомогательные Python-скрипты экспорта. Проверки выполнялись на локальной production-сборке с вымышленными demo-заказами.

## Обнаружено и исправлено

| Проблема                                                                                                        | Исправление                                                                                                                                                                                                                              |
| --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ключ гостевого заказа находился в query string и мог сохраняться в access-логах                                 | Новые ссылки используют фрагмент `#token=…`; API принимает только Bearer-заголовок. Ответы API запрещают кэширование. Старые ссылки на страницу преобразуются в браузере                                                                 |
| Лимит создания заказа опирался на подменяемый IP-заголовок; остальные чувствительные API не имели общих лимитов | Введены общие бюджеты на процесс и отдельные клиентские лимиты для заказов, расчёта корзины, webhook и интеграции; размер и срок жизни таблицы лимитов ограничены                                                                        |
| Уведомление с неизвестным ID могло инициировать авторизованный запрос к платёжному провайдеру                   | Обрабатываются только известные локальные live-платежи. Статус подтверждает повторный GET ЮKassa со сверкой суммы, валюты, metadata, признака test и paid; содержимое уведомления само по себе ничего не оплачивает                      |
| Недостаточно строгие ограничения входных данных и времени чтения тела                                           | Проверяются UTF-8, JSON-объект, MIME, размер и время чтения; добавлены проверки параметров интеграции и способов оплаты. Ошибки 500 не раскрывают внутренние сообщения                                                                   |
| Отсутствовала строгая политика исполнения скриптов                                                              | Добавлена CSP с новым случайным nonce для каждого документа, запретом сторонних скриптов и встраивания в iframe. Добавлены no-referrer, Permissions-Policy и HSTS. Inline-стили разрешены для существующих React style-атрибутов         |
| Ссылки и сохранённые в браузере данные требовали дополнительной проверки                                        | Оплата разрешает только HTTPS-адреса доменов ЮKassa/ЮMoney; документы — HTTP(S) без учётных данных; фотографии корзины — только известные локальные пути. Повреждённая корзина и недоступный localStorage не приводят к падению страницы |
| Оптимизатор изображений допускал произвольные локальные маршруты                                                | Разрешены только `/media/**` и `/products/**` без query string; ограничены дисковый кэш и перенаправления                                                                                                                                |
| Открытое демо могло бесконечно накапливать заказы                                                               | Добавлена очистка старых demo-заказов до примерно 500 последних; live-заказы не удаляются                                                                                                                                                |
| Пользователь контейнера мог менять исходники приложения                                                         | Исходники принадлежат root; процесс работает от node. Запись разрешена в приватную базу и кэш изображений. Файл базы имеет права 0600                                                                                                    |
| У экспортёров были предсказуемые временные каталоги и недостаточно строгие правила обработки внешних данных     | Приватные каталоги/случайные временные имена, очистка активного HTML, проверка ссылок и путей. Сетевой экспорт ограничен ANADO, перенаправлениями внутри него и ответом до 20 МиБ                                                        |
| В установленном Pillow 12.3.0 были опубликованные advisories                                                    | Вспомогательные зависимости закреплены в `requirements-tools.txt`; Pillow обновлён до 13.0.0. В работающий Node.js-контейнер эта библиотека не входит                                                                                    |

SQL-запросы с пользовательскими значениями используют параметры. Поля сортировки выбираются из фиксированных вариантов, а полнотекстовый поиск собирается из ограниченного набора буквенно-цифровых токенов. Описания и характеристики выводятся как текст и структурированные таблицы через React; HTML из исходного сайта не исполняется.

## Проверки

- `npm audit`: **0 известных уязвимостей** по полученной базе advisories.
- `pip-audit -r requirements-tools.txt`: **0 известных уязвимостей** в закреплённых инструментах и их разрешённых зависимостях после обновления.
- `bandit -r tools`: **0 срабатываний**. Обычные `assert` в браузерных тестах не являются обработкой недоверенных запросов и из тестов не удалялись.
- `npm test`: **19 успешных тестов**, включая пересчёт суммы сервером, идемпотентность, изоляцию заказов, неверные токены, CSRF, подмену IP-заголовков, лимиты, SQL-метасимволы, некорректный JSON и поддельные webhook.
- Python: **3 успешных теста** очистки HTML, безопасных URL/путей, запрета внешних запросов и перенаправлений; внешний сайт при этом не запрашивается.
- Production-сборка и TypeScript проходят. Браузерный smoke-тест проверяет каталог, мобильную навигацию, варианты товара, корзину и оформление/оплату demo-заказа без ошибок JavaScript и ответов 5xx.
- Браузерные security-проверки подтверждают уникальность nonce, блокирование внедрённого в HTML скрипта, восстановление повреждённой корзины, экранирование текста, защиту заказа, миграцию старой ссылки и запрет обращения оптимизатора к API.
- Docker-образ успешно собран и запущен с лимитом 512 МиБ. Обе браузерные проверки проходят и внутри контейнера; health-check подтверждает полный каталог. Проверены UID 1000, запрет записи в исходники, возможность записи в базу/кэш, права 0600 на базе и 0700 на её каталоге.
- В отслеживаемых исходниках не найдены совпадения с проверенными форматами приватных ключей и токенов GitHub/AWS/ЮKassa; секретные `.env` не отслеживаются. Это проверка по шаблонам, а не доказательство отсутствия любых секретов.
- Повторно проверен распространяемый `data/catalog-demo.sqlite.gz`: **5 756 товаров, 11 972 варианта, 131 категория, 0 заказов, 0 пакетов синхронизации**. Локальная база с заказами в Git и Docker build context не включается.

## Границы проверки и подготовка реальной оплаты

Это проверка кода и воспроизводимых локальных сценариев. Она не гарантирует отсутствия всех уязвимостей и не заменяет проверку инфраструктуры хостинга, системы 1С и настоящего магазина ЮKassa. Сканирование ОС базового Docker-образа и внешний пентест Render не проводились; проверяется именно приложение и перечисленные зависимости. Реальные платежи, возвраты и обмен с рабочей 1С не выполнялись.

**Текущая проверка остатка не создаёт атомарный резерв в 1С.** До подключения резерва, его отмены, отгрузки, фискализации и приёмочных проверок нельзя включать реальные онлайн-платежи. По умолчанию добавленный флаг `LIVE_PAYMENTS_ENABLED=0` блокирует их создание даже при `PAYMENT_MODE=live`; значение `1` — осознанное включение оператором после завершения работ, само резервирование оно не реализует. Уже созданные реальные платежи по-прежнему могут получать проверенные уведомления. Публичный demo-entrypoint всегда принудительно оставляет `PAYMENT_MODE=demo` и очищает настройки платёжных ключей и входящего обмена.

Лимиты запросов хранятся в памяти процесса и сбрасываются при рестарте. Для нескольких экземпляров, защиты от распределённой нагрузки и настоящих продаж нужны общие лимиты на хостинге, постоянная транзакционная база, резервные копии и мониторинг. Для новых заказов требуется сессия владельца; старые гостевые заказы доступны по секретной ссылке, её нельзя публиковать. Старые query-ссылки могли оставить ключи в прежних серверных журналах; доступ к таким журналам следует ограничить.


## Дополнение: аккаунты и счета, 25.10.2026

Добавлены scrypt-пароли, хешированные серверные сессии, HttpOnly/SameSite cookie и Secure на HTTPS, серверная привязка заказа к пользователю, проверка владельца при чтении заказа/счёта и тестовой оплате. Импорт из админки требует серверную роль admin; смена роли доступна только локальной административной команде. У счетов из 1С проверяются сумма заказа, число строк и границы НДС, повторы идемпотентны. GUID подтверждения заказа сохраняется и защищён от замены.

Проверки: 26 модульных тестов; браузерные сценарии регистрации/входа/выхода, изоляции заказов, запрета админского импорта покупателю, печати счёта и адаптивности 320–1440 px; отдельный локальный HTTP-тест обмена и сохранения данных после перезапуска. Новый Docker entrypoint допускает явно настроенный live-режим, но не включает онлайн-платежи. Настоящая 1С не подключалась. Подтверждение email, восстановление пароля и MFA ещё не реализованы; почтовый адрес не является проверенной личностью. Реальные продажи требуют постоянного хранилища и завершения настроек, перечисленных в ACCOUNTS_AND_1C.md.
