# Посмотреть сайт на компьютере и телефоне

Для публичной демонстрации не нужен доступ к серверам ANADO. Подготовлены `Dockerfile` и `render.yaml` для Web Service на **Render** с `plan: free`. Хостинг выдаёт HTTPS-адрес, который открывается с телефона и компьютера без общей сети Wi-Fi.

Для загрузки через браузер подготовлен `anado-render-demo.zip`: всего 10 файлов, каждая часть меньше 25 МБ. Распакуйте ZIP и загрузите **все файлы из полученной папки** в корень своего GitHub-репозитория через Add file → Upload files. Сам ZIP в GitHub загружать не нужно. После сохранения файлов выполняйте шаги Render ниже. Пакет собирается командой `python tools/package_render_demo.py`; исходники и фотографии находятся внутри проверяемых контрольными суммами частей и распаковываются при сборке контейнера.

## Что нужно сделать владельцу аккаунта

Если в GitHub уже видны папки `app`, `components`, `lib`, `catalog/images`, а также `Dockerfile` и `render.yaml`, используйте этот полный исходный проект: дополнительные файлы из ZIP не нужны. В Render можно выбрать **New → Web Service**, этот репозиторий, ветку `main`, язык **Docker**, пустой Root Directory, путь `./Dockerfile` и тариф **Free**, затем **Deploy Web Service**. Альтернативный вариант — Blueprint с тем же репозиторием.

1. Сохранить подготовленные файлы проекта в своём GitHub-репозитории. Для запуска нужны исходники приложения, `data/catalog-demo.sqlite.gz`, `data/anado-categories.json`, фотографии `catalog/images`, папка `public`, `Dockerfile`, `render.yaml`, `package.json`, `package-lock.json` и конфигурация Next.js/TypeScript. Большой исходный JSONL и личная `.local`-база не нужны.
2. Войти на [render.com](https://render.com/) через GitHub и разрешить доступ к этому репозиторию.
3. Выбрать **New → Blueprint**, подключить репозиторий и ветку с подготовленным сайтом. Render прочитает `render.yaml`.
4. Проверить, что выбран **Free**, и запустить создание сервиса. При отсутствии Free в вашем аккаунте не выбирать платный тариф автоматически: остановиться и уточнить доступность бесплатного размещения.
5. После успешного развёртывания открыть адрес сервиса, выданный Render. Тот же адрес подходит для телефона и компьютера.

Вход в аккаунт и подключение GitHub выполняет владелец. Пароли и коды входа в переписку не отправлять. Сервис Render из этой среды ещё не создан; публичного адреса пока нет. Для полностью автоматического создания сервиса дополнительно потребуется доступ к аккаунту хостинга.

## Ограничения демонстрации

- Настройка запрашивает бесплатный тариф, но доступность, квоты, необходимость проверки аккаунта и действующие условия определяет Render. Перед запуском проверить [официальные условия](https://render.com/docs/free). Прямой доступ к документации Render из текущей среды ограничен сетью; текущие коммерческие условия здесь не подтверждены.
- Бесплатный сервис может засыпать: первое открытие после простоя будет медленнее.
- Постоянный диск не настроен. Тестовые заказы в SQLite могут исчезать при перезапуске или новом развёртывании. Исходный каталог восстанавливается из чистого архива.
- Демонстрационный запуск принудительно использует `PAYMENT_MODE=demo` и не подключает рабочие ключи ЮKassa или 1С. Оплата проверяется без списания денег; используйте вымышленные контакты.
- Для магазина с настоящими заказами нужны постоянная база, резервирование, подключение 1С:УТ, ЮKassa и настройки чеков. Этот бесплатный вариант предназначен для просмотра и согласования сайта.

## Проверка контейнера разработчиком

```bash
node scripts/export-demo.mjs
docker build -t anado-demo .
docker run --name anado-demo --publish 3000:10000 anado-demo
```

При сборке в текущей облачной среде нужен её доверенный сертификат TLS-прокси: передайте `--secret id=build_ca,src=/usr/local/share/ca-certificates/environment-proxy-ca.crt` в `docker build`. Сертификат используется только во время установки зависимостей и не сохраняется в образе; проверка TLS остаётся включённой. На обычном хостинге этот параметр не требуется.

`GET /api/health` должен вернуть `{"ok":true,"catalogCards":5756}`. Контейнер запускается от пользователя `node`; загружается только публичный каталог, без существующих заказов и секретов. Фотографии работают из локальных файлов. Возможность сборки и работы контейнера проверяется отдельно от развёртывания у провайдера.
