# ANADO — интернет-магазин

Next.js 16 / React 19 / TypeScript, Node.js 24 и SQLite. Каталог и фотографии перенесены с **ANADO**; визуальный ориентир — ATOL. Фирменные акценты: синий `#008CBB` и зелёный `#8DCC00`. Шрифты Manrope и Golos Text поставляются локально.

## Запуск

Для публичной демонстрации без своего сервера подготовлен бесплатный вариант Render: [инструкция](docs/FREE_PREVIEW.md).

```bash
cd /workspace/soite
npm ci --no-audit --no-fund
npm run prepare:catalog
npm run dev
```

Для проверки производственной сборки:

```bash
npm run build
npm run start
```

Node.js **24+** обязателен: используется встроенный `node:sqlite`. База создаётся в `.local/anado.sqlite`; переопределение — `ANADO_DB`. При повторном импорте существующие заказы, синхронизированные цены и остатки сохраняются. `--force` повторно читает исходный каталог, но не обнуляет цены из 1С. Фотографии доступны через относительную ссылку `public/media → catalog/images`: оба каталога должны входить в поставку.

Если полного JSONL нет, `prepare:catalog` умеет восстановить начальную базу из `data/catalog-demo.sqlite.gz`. Этот чистый архив содержит только публичный каталог, без старых заказов. Demo-контейнер собирается из него; для обновления исходного архива используйте `npm run export:demo` в рабочем каталоге с полной выгрузкой.

## Что работает

- Главная с фирменным логотипом, решениями, сервисом, FAQ, плавной прокруткой и анимациями с учётом reduced motion.
- Все **19 основных разделов / 112 подразделов**, 5 756 карточек и 11 972 варианта ANADO. Данные читаются из SQLite, большой JSONL не попадает в браузер.
- Поиск по русским названиям и артикулам, сортировка, фильтр указанной цены, страницы по 24 товара.
- Карточки с исходными описаниями, таблицами характеристик, комплектациями, артикулами и документами. Пропуски и архивные модели обозначены явно.
- Корзина с сохранением в браузере; оформление с самовывозом / доставкой, картой / СБП / счётом; сохранение заказов на сервере.
- Серверная проверка состава и суммы, повторных запросов и уведомлений ЮKassa. Доступ к заказу — по непредсказуемому токену.
- Демонстрационная оплата без списания денег. Demo-заказы не выгружаются в 1С и не отправляются продавцу.
- Контакты двух офисов, страницы решений, услуг, компании, доставки и обработки данных.
- Перенаправления старых канонических адресов товаров и исходных категорий на новые страницы.

## Проверки

```bash
npm run typecheck
npm test
npm run build
# При запущенном сервере, установленном Python Playwright и /usr/bin/chromium:
python tests/browser-smoke.py
python tests/browser-security.py
# Для вспомогательных Python-скриптов экспорта каталога:
python -m pip install -r requirements-tools.txt
python -m unittest discover -s tests -p 'security_tools_test.py'
```

Тесты сервера используют отдельную временную базу. Браузерная проверка создаёт только demo-заказы с вымышленными контактами. Отчёт и снимки экрана — `test-results/` (не входят в Git).

Проверка безопасности исходников и зависимостей: [отчёт от 24.10.2026](docs/SECURITY_REVIEW.md).

## Подключение реальных платежей и 1С

По умолчанию `PAYMENT_MODE=demo`. Рабочий эквайринг и база 1С пока **не подключены**. Подробный контракт и порядок подключения: [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

Потребуются договор/магазин ЮKassa, ключи в защищённых настройках хостинга, публичный HTTPS-адрес, настройки чеков и сопоставление с номенклатурой 1С:УТ. Актуальные цена, остаток и налоговые реквизиты каждой позиции должны поступать из 1С. Историческая цена с исходного сайта сама по себе не разрешает реальную онлайн-оплату.

Это подготовленная для разработки версия магазина. До публичных продаж необходимо подключить рабочую 1С, резервирование, фискализацию и реальные реквизиты продавца. Страница обработки персональных данных пока является проектом. Отправка email/SMS, кабинет покупателя, возвраты и администрирование заказов в интерфейсе пока не реализованы; заказы доступны через защищённый API обмена.

SQLite подходит для текущей среды и одного экземпляра приложения. Для нескольких экземпляров понадобится общая транзакционная БД. Размещайте `.local` на постоянном диске и делайте резервные копии; `next start` должен работать под менеджером процессов.
